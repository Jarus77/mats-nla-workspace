# Do NLAs read what the model can't say?

A MATS 12.0 (Neel Nanda stream) research project on Qwen3.6-27B. It asks whether natural-language autoencoders (NLAs) and Oracle Lens read content in a model's activations that sits outside its verbal "workspace" (the J-space), or whether their success comes from re-solving the prompt text.

**Status:** prep and pilot work are complete; the confirmatory run is pre-registered for Oct 19 – Nov 1, 2026. All pilot numbers come from declared pilot splits that are excluded from the main analysis.

## Findings so far

**Solid**
- WorkspaceBench (4 regex families, layer 42, n = 400) can't separate reading the activation from re-solving the prompt. A text-only model given the prompt scores 0.89; given only the readers' outputs, 0.60 (NLA) and 0.56 (Oracle Lens). Adding the outputs to the prompt doesn't help (0.88).
- Oracle Lens's published lead comes from per-item any-layer selection, which adds 0.08–0.22. At the same layer the NLA ties or beats it.
- The standard "probe survives J-space removal" test can't tell features apart. Every feature keeps ≥ 98% of its probe accuracy, topic included, and removing a random subspace of the same rank gives the same result.
- Characters since the last newline ("col") is outside the J-space under two lenses, causally used by the model, and keeps 79% of its effect after J-removal, against 12–23% for every other feature tested.

**Pilot (to be confirmed)**
- Both readers track in-J features (language, tense) at matched steering strength; neither describes col.
- Two candidate narrow channels respond to col: Oracle Lens's next-token continuation channel, which moves one-for-one with the model's own newline decision, and one NLA phrasing.
- Under a planted bridge entity, the NLA rewrites the prompt's clue to fit the activation (12/12).
